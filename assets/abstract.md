# CondaTainer: a tool for streamlining reproducible high-throughput analysis from pipelines to figures

A computational analysis is defined by more than the code used to execute it. It also depends on the version of every software tool, package, and reference data. Therefore, two computing systems running the same script can give different results.

Conda helps address this problem by creating self-contained software environments with fixed package versions. However, on a shared computing cluster, it has a practical limit: a single environment can contain tens of thousands of files, making environments slow to create and exhausting user storage quotas. We developed CondaTainer, a tool that packs an entire environment into one file. When an analysis is launched, the file is mounted and presented to the user as a standard directory. The environment behaves as before, while the cluster manages one file rather than tens of thousands. The file can be centrally stored, shared across users, and distributed with publications to improve both computation efficiency and reproducibility.

Packing an environment into one file also makes it something that can be moved. CondaTainer publishes finished environments, tools, and reference data to any standard OCI container registry, the same infrastructure that already distributes Docker images, and pulls them back instead of rebuilding, so a reference index that costs hours to construct is built once and downloaded everywhere else. Each artifact records how it was built, and a project keeps those records, together with the recipes behind them, in a small lock directory committed alongside the analysis code. From a fresh checkout on a machine that has never run CondaTainer, one restore command reassembles the exact environment the analysis ran with, downloading what has been published and rebuilding from the recorded recipes what has not. The software and reference data therefore travel with the analysis, under version control, rather than as an instruction to install something and hope.

Downstream analysis places different demands. Following raw data processing, workflows shift toward code development, data exploration, and figure generation, usually in interactive applications such as RStudio. These interactive tools can be difficult to run on clusters, while large, memory-intensive datasets, such as single-cell data, are often impractical to analyze on personal computers. CondaTainer overcomes this challenge by launching interactive applications directly on computing clusters with a single command and connecting users to them, allowing interactive work takes place where the data and computing capacity are. Each project receives a writable, single-file workspace in which new packages can be installed and subsequently shared to reproduce the analysis environment.

By combining efficient environment management, registry-based distribution, project-level pinning, and interactive computing, CondaTainer provides a user-friendly workflow that streamlines every stage of high-throughput data analysis to generate reproducible results.
